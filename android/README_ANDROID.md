# WaveGrid on Android (APK)

Legend: **[V]** verified by reading JUCE 8.0.4 sources in `build/_deps/juce-src`;
**[S]** syntax-checked here (host clang / CMake stub); **[A]** assumed / from memory, not verifiable on this Mac.
**Nothing Android has been compiled or run** - this Mac has no Android SDK/NDK/Gradle, and JDK 25 only.

## What exists

| Path | Purpose |
|---|---|
| `Source/android/AndroidMain.cpp` | `JUCEApplication` hosting `WaveGridProcessor` + `WaveGridEditor` via `AudioProcessorPlayer` + `AudioDeviceManager` [S] |
| `cmake/WaveGridAndroid.cmake` | target `WaveGridAndroid` (shared lib named `juce_jni`), only active when `CMAKE_SYSTEM_NAME=Android` [S, stubbed] |
| `android/CMakeLists.txt` | CMake entry point used by Gradle (fetches or reuses JUCE, includes the file above) |
| `android/{settings,build}.gradle`, `app/build.gradle`, `app/src/main/AndroidManifest.xml` | hand-written Gradle project that packages the .so + JUCE's Java classes into an APK |
| `android/res/` | launcher icons (made separately); referenced as a Gradle res dir |

## Key finding [V]

JUCE 8.0.4's CMake API does **not** produce APKs: `docs/CMake API.md` says "Android targets are not currently supported".
What does exist in `JUCEUtils.cmake` / `JUCEModuleSupport.cmake` is partial plumbing: `juce_add_gui_app` creates a SHARED library on Android,
juce_audio_devices pulls in Oboe, juce_core adds NDK `cpu-features.c`, `juceaide` is built for the host automatically.
Packaging (Java classes, manifest, Gradle, signing) is only generated by the **Projucer**. So this project uses
JUCE's CMake for the native lib and a hand-written Gradle project (modelled on the Projucer output in
`extras/AudioPluginHost/Builds/Android`) for the APK. The CMake-for-Android path is JUCE-undocumented, so expect to fix a
compile/link error or two on the first real build [A].

Other verified facts: JUCE's Java side does `System.loadLibrary("juce_jni")` (hence `OUTPUT_NAME juce_jni`); Projucer uses
NDK `26.2.11394342`, `compileSdk/targetSdk 34`, AGP `8.4.1`, Gradle `8.6`, CMake `3.22.1`, `ANDROID_STL=c++_static`,
`ANDROID_WEAK_API_DEFS=ON` (needs NDK 26+); `ICON_BIG` is ignored on Android (icons are only converted for mac/win/iOS), so icons
are plain Android resources; audio uses Oboe (`JUCE_USE_ANDROID_OBOE=1` default) with OpenSL ES fallback; input-less streams do
not need RECORD_AUDIO; Bluetooth MIDI needs `RuntimePermissions::bluetoothMidi` (BLUETOOTH_SCAN / FINE_LOCATION); USB MIDI uses
`android.media.midi` with no permission.

## 1. Install tools (macOS) - multi-GB, owner action

```bash
# JDK 17 (Gradle 8.6 / AGP 8.4.1 do NOT work with the JDK 25 currently installed)
brew install --cask temurin@17
export JAVA_HOME=$(/usr/libexec/java_home -v 17)

# Android command-line tools + CMake 4 is already installed; Android needs its own 3.22.1 via sdkmanager
brew install --cask android-commandlinetools      # or install Android Studio instead
brew install gradle                               # only used once, to create the gradle wrapper

export ANDROID_HOME=$HOME/Library/Android/sdk
mkdir -p $ANDROID_HOME
echo 'export ANDROID_HOME=$HOME/Library/Android/sdk' >> ~/.zshrc
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 17)' >> ~/.zshrc
echo 'export PATH=$PATH:$ANDROID_HOME/platform-tools' >> ~/.zshrc

yes | sdkmanager --sdk_root=$ANDROID_HOME --licenses
sdkmanager --sdk_root=$ANDROID_HOME \
  "platform-tools" "platforms;android-34" "build-tools;34.0.0" \
  "ndk;26.2.11394342" "cmake;3.22.1"
```
Android Studio alternative: install it, then SDK Manager -> SDK Platforms: Android 14 (API 34); SDK Tools: NDK (Side by side) 26.2.11394342,
CMake 3.22.1, Platform-Tools. Then open the `android/` folder (accept "use JDK 17" / do not upgrade AGP).
Package names are Projucer-derived [V for versions, A for exact sdkmanager spelling].

## 2. Build a debug APK

```bash
cd /Users/deepganguly98/Desktop/WaveGrid/android
echo "sdk.dir=$ANDROID_HOME" > local.properties
gradle wrapper --gradle-version 8.6            # once; creates ./gradlew
# JUCE tree: defaults to ../build/_deps/juce-src (run the desktop cmake configure once so it exists), or pass -PjuceDir=
./gradlew assembleDebug
# -> android/app/build/outputs/apk/debug/app-debug.apk
```
Faster iteration: `-Pandroid.injected.build.abi=arm64-v8a` is already the only ABI. For an emulator add `"x86_64"` to `abiFilters`
in `app/build.gradle`.

Manual native-only configure (for debugging CMake errors, skips Gradle) [A]:
```bash
cmake -S android -B build-android -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$ANDROID_HOME/ndk/26.2.11394342/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-24 -DANDROID_STL=c++_static \
  -DANDROID_WEAK_API_DEFS=ON -DCMAKE_BUILD_TYPE=Release \
  -DWAVEGRID_JUCE_DIR=$PWD/build/_deps/juce-src
cmake --build build-android
```

## 3. Install and run

```bash
adb devices                                   # enable Developer options + USB debugging on the phone first
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.deepaudio.wavegrid/com.rmsl.juce.JuceActivity
adb logcat | grep -i -E "juce|wavegrid|oboe"
```

## 4. Signed release APK / AAB

```bash
keytool -genkeypair -v -keystore ~/wavegrid-release.jks -alias wavegrid \
  -keyalg RSA -keysize 2048 -validity 10000
# NEVER commit the keystore or passwords. Put them in ~/.gradle/gradle.properties:
cat >> ~/.gradle/gradle.properties <<'EOP'
WG_KEYSTORE=/Users/deepganguly98/wavegrid-release.jks
WG_STORE_PASS=changeme
WG_KEY_ALIAS=wavegrid
WG_KEY_PASS=changeme
EOP
cd android
./gradlew assembleRelease     # -> app/build/outputs/apk/release/app-release.apk (installable, sideload)
./gradlew bundleRelease       # -> app/build/outputs/bundle/release/app-release.aab (Play Store)
```
Without `WG_KEYSTORE` the release build is signed with the debug key (installable, but not for the Play Store).

## CMake wiring (CMakeLists.txt)

**None required** to build the APK: Gradle uses `android/CMakeLists.txt`. Optional, if you want
`cmake -DCMAKE_TOOLCHAIN_FILE=<ndk> ...` against the root file too, make these edits to the root `CMakeLists.txt`:

1. Extend the platform branch at the top (before the final `else()`):
```cmake
elseif(CMAKE_SYSTEM_NAME STREQUAL "Android")
    set(WG_FORMATS Standalone)   # unused on Android; plugin formats don't exist there
```
2. Immediately after `FetchContent_MakeAvailable(JUCE)`:
```cmake
if(CMAKE_SYSTEM_NAME STREQUAL "Android")
    include(cmake/WaveGridAndroid.cmake)
    return()
endif()
```
(Then the desktop `juce_add_plugin(...)` is skipped on Android.) The root `project()` only enables C and CXX; also add `ASM`
to `LANGUAGES` if you use this route [A].

## Behaviour and limitations on Android

- **Editor scaling**: `RootComponent` gives the unchanged editor a virtual size of at least 760x560 and applies an
  `AffineTransform` scale (0.3x-1.6x) so it fills the screen; safe-area insets respected; app locked to landscape
  (`sensorLandscape`, matching the iOS config). Text on a ~6" phone ends up small (about 0.5x); tablets are fine.
- **Multi-touch**: unchanged `GridSurface`, keyed by `MouseEvent::source.getIndex()`; JUCE's Android peer delivers each pointer
  as its own mouse source [A: verify on device]. No pressure/force on most phones, so `yIsPressure` path is used.
- **Hover**: `ReadoutSlider::onHover` (value readout on hover) never fires on touch; knob values are not shown while dragging
  unless the editor already does it in `mouseDrag`. Keyboard handling (`keyPressed`, A-W-S-E piano) only works with a
  physical/BT keyboard. `grabKeyboardFocus()` in `mouseDown` is harmless.
- **Latency**: Oboe low-latency (AAudio) stream, device-default buffer (typically 96-192 frames at 48 kHz, ~4-12 ms in the
  buffer, plus device-dependent output latency; budget tens of ms on many phones). Tune later with
  `AudioDeviceManager::AudioDeviceSetup::bufferSize`. Not measured [A].
- **MIDI**: USB-MIDI and Bluetooth-MIDI inputs (e.g. Linnstrument, Roli) are enabled automatically and rescanned every 3 s.
  Bluetooth asks for permission at startup. MPE over USB works only if the device sends class-compliant MIDI 1.0 packets
  [A]. **MIDI out (the merged grid MIDI) is not routed anywhere** on Android; the processor still produces it.
- **Lifecycle**: audio device is closed on `suspended()` and reopened on `resumed()`; held touches are lost on background.
- **Presets**: stored under JUCE's `userApplicationDataDirectory` (app-private storage on Android).
- **No edits to existing sources were needed.** `PluginProcessor.h` uses `JucePlugin_Name`, which the Android target defines
  (`JucePlugin_Name="WaveGrid"`). Anything else that later includes `JucePlugin_*` macros must be defined the same way.
- Not done: Play Store assets, adaptive-icon check (icons come from `android/res`), armeabi-v7a/x86_64 ABIs (one line in
  `app/build.gradle`), audio-thread priority tuning, `x86_64` emulator audio quality.

## Troubleshooting

- `Unsupported class file major version 69` / Gradle crashes at start -> running on JDK 25; `export JAVA_HOME=$(/usr/libexec/java_home -v 17)`.
- `JUCE not found at ...` -> run the desktop cmake configure once, or `./gradlew assembleDebug -PjuceDir=/path/to/JUCE`.
- `SDK location not found` -> create `android/local.properties` with `sdk.dir=...` or export `ANDROID_HOME`.
- `NDK ... did not have a source.properties` / NDK not found -> install exactly `ndk;26.2.11394342`; do not rely on NDK 27+
  (`cpufeatures` sources, used by JUCE's CMake via `${ANDROID_NDK}/sources/android/cpufeatures`, may be absent) [A].
- `CMake '3.22.1' was not found` -> `sdkmanager "cmake;3.22.1"` (Gradle will not use Homebrew's CMake 4).
- Link error `cannot find -lGLESv3`/`EGL` or undefined `AFontMatcher` symbols -> ensure `ANDROID_WEAK_API_DEFS=ON` and
  `ANDROID_PLATFORM=android-24`.
- App crashes at launch, logcat `UnsatisfiedLinkError: libjuce_jni.so` -> the target's OUTPUT_NAME or ABI filter is wrong;
  check `unzip -l app-debug.apk | grep lib/`.
- No sound -> `adb logcat | grep -i oboe`; check the phone isn't in silent mode and that "WaveGrid audio init" isn't logged with an error.
- Bluetooth MIDI device not listed -> accept the Nearby devices / Location prompt, pair the device in the Android Bluetooth
  settings first; USB: use OTG adapter, device must be class-compliant.
- `INSTALL_FAILED_UPDATE_INCOMPATIBLE` -> `adb uninstall com.deepaudio.wavegrid` (debug and release keys differ).
- juceaide host build fails during configure -> needs a working host compiler (Xcode CLT); unrelated to the NDK.
- C++20 errors from NDK clang -> NDK 26.2 ships clang 17, which supports the C++20 features used here; if a specific
  one fails, set `CMAKE_CXX_STANDARD 17` in `android/CMakeLists.txt` [A].
